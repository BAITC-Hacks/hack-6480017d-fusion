# Fusion: план завершения MVP

**Текущий объём по последнему уточнению пользователя:** один OpenAI составляет справку по выбранному узлу. Выбрана gpt-5.4-mini с reasoning low; фактический ID и результат видны в приложении. Прежняя обязательность NVIDIA отменена: она отключена по умолчанию (`NVIDIA_ENABLED=false`) и не вызывается. Опциональный адаптер сохранён для явного включения через `NVIDIA_ENABLED=true`; его проверка не блокирует сдачу.

## Готово: READY — FREEZE CORE

Реализованы аудит, расчёт ролей, кластеров и приоритета, три CSV, API результатов, интерактивный граф, поиск любого GID, карточка с ограничениями и AI-разбор со ссылками на факты. Закрыты P0: полные направленные потоки с суммами, пять вкладов priority с множителем и why, ранг среди всех узлов и статус наблюдаемости. Добавлена сводка кластера с оборотом и лидерами. На 23 сентября 2026 прошли **83 backend-теста**, сборка frontend и проверка зависимостей. Шесть реальных справок OpenAI уже проверены; повторять платные вызовы для неизменённой интеграции не нужно. Подробности — [PROGRESS.md](PROGRESS.md) и [AI_VALIDATION.md](AI_VALIDATION.md).

[Аудит готовности](TECHNICAL_AUDIT.md) подтвердил воспроизводимость всех трёх CSV, включая новую копию HEAD с отдельной venv без `.env`. Полный процесс расчёта: 1,20 с в основном окружении и 21,586 с при первом запуске свежего окружения. После исправлений интерфейса все три CSV побайтно прежние. Формулы, роли, Louvain и веса заморожены.

1. Перед выступлением проверить запущенное приложение: `.venv/bin/python scripts/run_local.py --check`.
2. Использовать [трёхминутное демо](DEMO.md): #5 → потоки и основания → #1/#2 → depth=4 → кластер → CSV. Пользовательский путь проверен в браузере; команде остаётся проговорить текст вслух.
3. Передать три файла из `artifacts/` вместе с материалами сдачи; при необходимости воспроизвести их одной командой README.
4. До защиты новые метрики и AI-сценарии не добавлять. **Betweenness — P2**, отдельный режим Bridge candidates только после основной защиты/при явно выделенном времени; не смешивать с текущим score.
5. Оставить серверы включёнными. При изменении исходных данных нужен пересчёт и перезапуск, иначе core не трогать.

## Продукт и границы

Fusion помогает AML-аналитику выбрать, кого проверять первым, и увидеть основания в графе переводов. Роли и приоритет — объяснимые гипотезы по наблюдаемым связям, а не утверждения о виновности. Python детерминированно рассчитывает граф, метрики, роли, кластеры, приоритет и три CSV без LLM и интернета после установки зависимостей.

В интерфейсе доступны топ-20, поиск любого GID, включая изоляты и depth=4, выбор кластера, окраска по ролям/кластерам и масштаб. Предел UI — 250 узлов области с явными счётчиками; API допускает до 500. Граф, карточки и полные CSV используют один снимок расчёта при старте. После замены parquet нужен перезапуск backend; API не пишет в `artifacts/`.

Не добавлять: обучение/GNN, внешний сбор сведений, распознавание личности, онлайн-банковские интеграции, базу данных, аккаунты, универсальный чат, произвольные форматы загрузки, облачный деплой, агентные циклы и массовую LLM-обработку всех узлов.

## AI-сценарий

1. Кнопка «AI-разбор» отправляет выбранный GID строкой. Backend формирует пакет одного узла: 24 факта, максимум 8 направленных связей, evidence_id, источники и ограничения. Весь датасет внешнему API не передаётся.
2. OpenAI формирует JSON-справку: гипотеза, основания со ссылками, ограничения, следующие проверки. Backend проверяет схему, ссылки и допустимые GID. Модель не меняет роли или скоры.
3. UI показывает справку, ссылки на локальные факты и настоящий статус API, кеша или ошибки. На новый разбор без кеша — один вызов OpenAI, без скрытых повторов или переписывания ответа через модель.
4. Таймаут ограничен сервером; текущая величина видна в `/api/ai/status`. Кеш в памяти живёт час и учитывает данные, правила, пакет, промпт и модель. Повторные клики не дублируют выполняющийся разбор, явное обновление обходит кеш. Перезапуск очищает задачи и кеш.
5. При ошибке OpenAI показывается помеченная локальная справка: это не ответ модели. Отключённая NVIDIA не делает успешный разбор OpenAI неполным. При её явном включении допустима отдельная рецензия по тем же фактам, максимум вторым вызовом; мнение рецензента также может быть ошибочным.
6. Реальные ответы OpenAI проверяются на шести разных узлах, обязательно включая depth=4 и изолированный seed. Один успешный ответ или корректная JSON-схема не заменяют проверку качества. Не заявлять измеренную точность ролей: эталонной разметки нет.

Серверный шаблон — `backend/.env.example`; ключ OpenAI помещается в `backend/.env`, исключённый из Git. Модель задаётся через `OPENAI_MODEL`, фактически выбранный ID показывается в статусе и ответе. Backend загружает настройки при старте; после изменения нужен перезапуск. Для базового режима NVIDIA-ключ не нужен. Оба сервера запускаются `.venv/bin/python scripts/run_local.py`, проверка без изменения процессов — с флагом `--check`. Установка и проверка — [README](../README.md), подробный контракт — [AI_DESIGN.md](AI_DESIGN.md).

## Демо и резерв

[DEMO.md](DEMO.md) содержит временные блоки и шесть вычисленных примеров: сводка и топ-лист → кандидат в транзит → справка OpenAI и источник → граница depth=4 → кластер → три CSV. GID не зашиты в алгоритм. Кеш показывать как кеш; fallback не выдавать за ответ API. В исходном ТЗ предусмотрено пять минут: дополнительное время можно использовать для изолированного seed и ограничений выборки.

Если времени или сети не хватает, сохранить локальный расчёт, обязательные CSV, поиск, объяснимость и ограничения данных. При сбое OpenAI показать локальную справку с честным статусом, не добавлять новые AI-функции. Промпт `prompts/01_START.md` остаётся историческим описанием первого этапа; повторно создавать каркас не нужно.
