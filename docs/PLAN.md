# Fusion: план MVP на 3.5 часа

## Продукт

Fusion помогает AML-аналитику выбрать, кого проверять первым, и увидеть основания в графе переводов. Роли и приоритет — объяснимые гипотезы на основе наблюдаемых связей, а не утверждения о виновности.

## Минимальный объём

Сделать: загрузку локальных данных, числовые признаки, шесть ролей с формальными правилами, кластеры, ранжирование, три CSV, направленный граф, поиск gid, карточку узла с ограничениями наблюдения. После основных функций реализовать обязательный AI-разбор с обоими API: OpenAI-аналитик и NVIDIA-рецензент. Технические границы описаны в AI_DESIGN.md. При ошибке API базовое объяснение доступно локально, но полным AI-разбором оно не считается.

Не делать: обучение/GNN, внешний сбор сведений, распознавание личности, онлайн-банковские интеграции, базу данных, аккаунты пользователей, универсальный чат, загрузку произвольных форматов, облачный деплой, многошаговые агентные циклы и массовую LLM-обработку всех узлов.

## Работа промптами

Первый промпт готов в prompts/01_START.md. Следующие выдаются после проверки результата предыдущего: расчётный модуль → интерфейс → AI-разбор с обоими API → проверка и демо. Не тратить первый этап на дизайн и LLM.

## Отдельный AI-этап после расчёта и интерфейса

Уточнение пользователя заменяет прежнее ограничение одним LLM-провайдером: **OpenAI и NVIDIA обязательны**, NVIDIA не резерв. Это требование продукта Fusion; в исходном кейсе AI остаётся опциональным. Граф, роли, кластеры, приоритет и CSV вычисляются детерминированно Python и работают без обоих API.

1. Кнопка «AI-разбор» передаёт на backend выбранный gid строкой. Backend формирует ограниченный пакет одного узла с evidence_id, источниками, признаками и флагами неполноты наблюдения. Внешним API не отправляется весь датасет.
2. OpenAI готовит структурированную справку: гипотеза, основания со ссылками на факты, ограничения и следующие проверки. Backend валидирует структуру, ссылки и допустимые gid.
3. NVIDIA NIM получает тот же пакет и валидную справку. Рецензия ищет неподтверждённые утверждения, пропущенные ограничения и альтернативные объяснения. Мнение рецензента не эталон и не меняет роль или score.
4. UI показывает справку и замечания отдельно, со ссылками на факты и честными статусами вызовов. Нормальный разбор без кеша — два последовательных запроса, максимум один к каждому API; третьего вызова, агентных циклов и скрытых автоматических повторов нет. При ошибке — частичный результат или локальная справка с явной маркировкой, без фиктивного успеха обоих API.
5. Ограничить пакет и длину ответов; задать таймауты и кеш по данным, правилам, промптам и моделям. Подробности контракта, кеша и ошибок — в [AI_DESIGN.md](AI_DESIGN.md).
6. Выбрать конкретные модели по доступу аккаунтов, русскому языку, корректности ссылок и задержке. На 5–6 узлах (обязательно depth=4 и изолированный seed) проверить реальные ответы обоих API: неподтверждённые утверждения, пропуски ограничений, ссылки, ложные замечания и задержку. Не заявлять улучшение точности без измерения; согласие моделей не подтверждает гипотезу.

Серверный шаблон конфигурации — `backend/.env.example`: ключи и модели пустые, публичный NVIDIA_BASE_URL задан. На текущем этапе шаблон не загружается приложением; реальные секреты не читаются и не меняются. Зависимости и платные вызовы ради планирования не добавлять. Статус этапа 1 и проверенные команды — в [PROGRESS.md](PROGRESS.md) и [README](../README.md).

## Демо на 3 минуты

0:00–0:30 — вопрос «кого проверять первым?» и топ-лист. 0:30–1:20 — открыть рассчитанного кандидата на консолидацию, показать плательщиков, суммы и правило роли. 1:20–2:00 — поиск произвольного gid, направление переводов, кластер. 2:00–2:30 — узел depth=4 с предупреждением о границе наблюдения; справка OpenAI и замечания NVIDIA с честными статусами вызовов. 2:30–3:00 — выгрузки и воспроизводимый расчёт. Не зашивать демонстрационные ID в алгоритм. В исходном ТЗ предусмотрено 5 минут: на дополнительное время оставить ещё один узел и разбор ограничений.

## Если не успеваем

Сначала убрать анимации, дополнительные метрики и свободный чат. AI-сценарий сократить до одной кнопки, двух вызовов и двух текстовых блоков. При сбое одного API показать частичный результат, не выдавая его за полный сценарий с двумя провайдерами. На графе показывать выбранный кластер или ограниченное окружение найденного узла, явно обозначая сокращённое представление; сохранить поиск по всем узлам. Полный расчёт, обязательные CSV, объяснимость и обработка ограничений данных остаются приоритетом.
