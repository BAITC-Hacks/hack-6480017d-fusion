Уточнение требований Fusion: мы обязательно используем внутри приложения оба API — OpenAI и NVIDIA. NVIDIA больше не только резерв. Это уточнение заменяет прежние ограничения на одного LLM-провайдера.

Сохрани текущие наработки и продолжи текущий этап. Сейчас обнови AGENTS.md, docs/PLAN.md и серверный .env.example (без чтения или перезаписи реального .env), чтобы зафиксировать следующую архитектуру для отдельного AI-этапа после работающего расчёта и интерфейса:

1. Python детерминированно рассчитывает роли, кластеры, приоритет и CSV. Модели не меняют эти результаты.
2. По кнопке «AI-разбор» backend собирает ограниченный пакет фактов одного узла с evidence_id, источниками, признаками неполного наблюдения; gid только строками.
3. OpenAI формирует структурированную справку: гипотеза, основания со ссылками, ограничения и следующие проверки.
4. После проверки структуры backend передаёт этот же пакет и справку модели через NVIDIA NIM. Она ищет неподтверждённые утверждения, пропущенные ограничения и альтернативные объяснения. Рецензент может ошибаться; его мнение не является истинной разметкой и не меняет score.
5. UI показывает справку OpenAI и замечания NVIDIA отдельно, со статусами реальных вызовов и ссылками на факты. Два запроса на разбор, без третьего вызова и без циклов агентов. Кеш, таймауты, короткие ответы, локальная справка при ошибке. Нельзя показывать fallback как успешную работу обоих API.
6. Добавь в .env.example пустые OPENAI_API_KEY, OPENAI_MODEL, NVIDIA_API_KEY, NVIDIA_MODEL и NVIDIA_BASE_URL=https://integrate.api.nvidia.com/v1. Ключи только на сервере; не используй VITE_ для секретов. Конкретные модели выберем по доступу, русскому языку, качеству ссылок и задержке.
7. На AI-этапе проверь оба реальных API и сравни качество на 5–6 разных узлах, включая depth=4 и изолированный seed. Не обещай улучшение точности от двух моделей без измерения. Не устанавливай дополнительных зависимостей и не делай платных вызовов на текущем этапе только ради обновления плана.
